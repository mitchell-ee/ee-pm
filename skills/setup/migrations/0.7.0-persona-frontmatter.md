# 0.7.0 — add frontmatter to personas that predate the convention

**Applies when:** any `product/personas/*.md` lacks frontmatter, or has frontmatter missing
`type` / `slug` / `name`.
**Guard:** a persona that already has all three is **skipped, never rewritten**. If every persona
has them, this migration is a no-op — say so and move on.
**Requires:** `0.6.0-context-collapse.md` (it produces the persona files this annotates)
**Precedes:** —

## Why this is not optional

`slug` is a **load-bearing identifier**, not a stylistic field. A story's `Personas:` field names
personas by slug, and every other skill resolves against it. A persona file without one is a
dangling reference: stories point at a persona that cannot be found, and nothing errors — the
lookup just silently finds nothing.

This is the gap the 0.6.0 migration left. `0.6.0-context-collapse.md` splits a single
`personas.md` into one file per persona, but splitting does not invent frontmatter. Every
migrated persona is invalid against the convention 0.6.0 introduced until this migration runs.

## The target shape

Per `framework-setup` §Personas — that skill is authoritative, this migration only backfills:

```yaml
---
type: Persona
slug: repeat-buyer      # kebab-case; the identity other files reference
name: Repeat buyer      # display name
emoji: 🔁               # optional — story-map board rendering only
---
```

## Procedure

**This migration cannot be fully mechanical.** The slug is what stories resolve against, so a
wrong guess silently breaks every reference to that persona. The PM confirms each one.

For each `product/personas/*.md` missing frontmatter:

1. **Propose** `type: Persona`, plus:
   - `name` — from the file's `#` H1, verbatim.
   - `slug` — kebab-case of the H1, and **the filename is the strongest signal**: a file already
     named `repeat-buyer.md` almost certainly wants `slug: repeat-buyer`. Propose the filename
     stem and say that is what you did.
   - `emoji` — **propose nothing.** It is optional, board-rendering-only, and a persona without
     one renders no prefix. Offer to add one if the PM wants it; never invent one.
2. **Show the PM all proposed slugs at once**, as a table, before writing anything. Slugs are a
   namespace — seeing them together is how collisions and inconsistent conventions get caught.
3. **Ask the PM to confirm or correct each slug.** This is a *stop*, not a defect to work around.
   Proceeding on unconfirmed slugs is worse than not migrating: it produces files that look
   valid and resolve wrongly.
4. **Write the frontmatter** at the top of the file, preserving all existing content below.

## Cross-check the references

After writing, **grep the repo for each persona's slug** — story `Personas:` fields, activity
files, and story-map sidecars all name personas by slug. Report:

- A slug referenced by stories but matching no persona file → the PM confirmed a slug that
  differs from what stories already use. Ask which is correct before leaving it.
- A persona file no story references → not an error (a persona may be new or aspirational), but
  worth surfacing.

## Idempotence

Guarded per file on the presence of `type` + `slug` + `name`. A persona that already has them is
skipped, so re-running cannot overwrite hand-authored frontmatter — which matters, because a PM
who migrated by hand has already made exactly these judgment calls.
