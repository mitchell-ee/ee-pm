# 0.6.0 — collapse `product/context/` into `product/`

**Applies when:** `<root>/product/context/` exists.
**Guard:** if it doesn't exist, this migration is a no-op — say so and move on.
**Requires:** —
**Precedes:** `0.7.0-persona-frontmatter.md` (this migration produces the personas it annotates)

**Every skill in 0.6.0 reads `product/` directly**, so an unmigrated project's context is
invisible — the skills won't error, they'll just find nothing. That silence is the reason this
migration exists.

The move is mechanical and one-to-one, with one rename:

| Was | Now |
|---|---|
| `product/context/personas.md` | `product/personas/{slug}.md` — **one file per persona** (see `framework-setup` §Personas) |
| `product/context/principles.md` | `product/design-principles.md` |
| `product/context/backlog.md` | `product/backlog.md` |
| `product/context/opportunity-solution-tree/` | `product/opportunity-solution-tree/` |
| `product/context/opportunity-solution-tree/assumptions/` | `product/assumptions/` |
| `product/context/<anything else>` | `product/<same>` |

**Ask before moving, and use `git mv`** so history follows the file.

## The persona split

Report this separately — it is the one step that isn't a rename, because a single `personas.md`
becomes N files keyed by slug, and only the PM can confirm the slugs.

**Guard on the target, not just the source.** Before writing `product/personas/{slug}.md`, check
whether that file already exists. If it does, **skip it and say so** — do not overwrite. A PM who
already split their personas by hand has authored content there, and the source `personas.md`
being present says nothing about whether the split already happened.

Splitting produces files that still need frontmatter (`type`, `slug`, `name`). That is a separate
migration — `0.7.0-persona-frontmatter.md`, which this one `Requires:`-precedes. Run it after this
one, in the same session. Until it runs, the personas are structurally invalid: stories resolve
personas by slug, so a persona without one is a dangling reference. §7.3's persona check will
catch this and refuse to stamp the project.

## Cleaning up

Once `product/context/` holds nothing, remove it. **Verify with `git status`, not `test -d`** —
git leaves empty directory skeletons behind after a `git mv`, so the directory can persist on disk
while being empty as far as the repo is concerned. What matters is that no tracked file remains
under it.

If it still holds anything unrecognized, leave it and say so — don't guess at a home for a file
this skill doesn't know.

## Idempotence

Guarded on `product/context/` existing; after a successful run it is gone, so a re-run finds
nothing and does nothing. The persona split is additionally guarded on each target file, so
re-running cannot clobber hand-authored personas even if `personas.md` is restored.
